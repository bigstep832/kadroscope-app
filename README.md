# Kadroscope · Кадр

Русскоязычное приложение для управления командными проектами. Клиент написан на React, сервер на JavaScript. Локальная версия работает на Node.js 24 и SQLite. Сервер раздаёт собранный интерфейс и API с одного адреса.

## Запуск

Для запуска из репозитория нужен Node.js 24 или новее. В каталоге с `package.json` выполните

```sh
npm ci
npm run dev
```

SQLite создаст файл БД при первом запуске. Если вы скачали готовую сборку с каталогом `dist`, достаточно команды `npm start`.

Откройте http://127.0.0.1:4173. Команда dev собирает интерфейс и запускает сервер. При следующем запуске без изменений кода достаточно `npm start`. Для разработки после изменения файлов перезапустите `npm run dev`. Для тестов выполните `npm run build`, затем `npm test`.

## Первые шаги

При первом посещении создаётся отдельный демонстрационный проект «Редизайн платформы» с девятью задачами и примерами исполнителей. Это примеры данных, а не реальные аккаунты коллег. Через «Мой профиль» задайте имя, почту и пароль, чтобы входить с других устройств в тот же аккаунт. Без регистрации доступ связан с cookie текущего браузера.

Создайте пустой проект кнопкой «+» рядом с «Проекты». Откройте «Команда», выберите роль и создайте одноразовый код на 48 часов. Коллега должен открыть тот же экземпляр приложения и выбрать «Вступить в проект». Владелец создаёт приглашения, участник редактирует задачи, наблюдатель читает данные.

Открывайте карточку для редактирования срока, приоритета, категории, исполнителя и статуса. Задачи можно переносить между колонками мышью или менять статус в форме. В карточке доступны подзадачи, комментарии, файлы до 1 МБ и записи времени. Отчёты показывают распределение задач и фактическое время по участникам. Раздел уведомлений хранит последние 60 событий проекта.

## Календарь, команды и фокус

Во вкладке «Календарь» стрелки меняют неделю, а «Сегодня» возвращает текущую. Перетащите карточку на день, чтобы перенести срок, или в «Без срока», чтобы снять его. На телефоне дни идут вертикально. Для изменения без перетаскивания откройте карточку и поменяйте поле «Срок». Последний перенос можно отменить в уведомлении.

Нажмите Ctrl+K (⌘K на Mac) или кнопку «Команды» вверху. Палитра ищет задачи и действия текущего проекта. Стрелки выбирают результат, Enter открывает, Esc закрывает. Клавиша / переводит фокус в поиск на доске. Нажатие на столбец диаграммы в шапке открывает список задач выбранного статуса.

В карточке нажмите «Начать фокус». Таймер внизу можно поставить на паузу, продолжить или завершить кнопкой «Записать». Сервер сохраняет таймер для вашего профиля и проекта. Запись попадает в учёт времени с округлением вверх до минуты. У одного человека в проекте одновременно может быть одна сессия.

Кнопка «В архив» скрывает задачу с доски и календаря. В разделе «Архив» доступны просмотр и восстановление. Пока над задачей работает таймер, сначала завершите или отмените сессию. Ранее учтённое время сохраняется в отчётах. Существующая SQLite-база обновляется при следующем запуске.

## Хранение и подключение

Данные, в том числе файлы, хранятся в `data/kadr.sqlite`. Для резервной копии остановите приложение и скопируйте каталог `data`. Путь к файлу БД задаёт переменная `KADR_DB`. Порт задаёт `PORT`, сетевой интерфейс — `HOST` (по умолчанию `127.0.0.1`). Для проверки на одном компьютере используйте независимые профили браузера. Для команды нужен доступный всем экземпляр сервера. При размещении Node.js за пределами компьютера настройте HTTPS на обратном прокси.

Клиент получает локальные изменения через Server-Sent Events. Сервер проверяет роль и принадлежность каждой задачи проекту. При сохранении проверяется версия карточки: устаревшая правка возвращает HTTP 409. Пароли защищены PBKDF2 с индивидуальной солью, токены локальных сессий хранятся в виде хеша.

## Структура

- `client/` — интерфейс React, канбан, формы и отчёты.
- `server/api.mjs` — общий HTTP API.
- `server/auth.mjs` — учётные записи, сессии и идентификация на хостинге.
- `server/local.mjs` — локальный сервер, SQLite и рассылка обновлений.
- `drizzle/` — SQL-схема и журнал миграций.
- `scripts/build.mjs` — сборка клиента и Worker для Sites.
- `tests/workflow.test.mjs` — проверка совместной работы через HTTP на временной БД.

Для частной версии в Sites сборка создаёт Worker с привязкой D1 `DB`. Хостинг устанавливает личность через ChatGPT. На хостинге клиент проверяет изменения каждые 2,5 секунды на активной вкладке. Доступ к самому сайту и роль внутри проекта задаются отдельно. Локальная и размещённая БД независимы.
